Everyone who runs a deal on Henry's website calculator gets one email. Clicking it opens their report in the Closing Table OS, and asks them to set a password first if they don't have one.

1Know the flow: one email for everyone

The visitor fills in the calculator, their first name and email, and the 3 questions. Then:

New emailEmail already has an account
AccountCreated automatically, no password yetNothing new is created
DealSaved to their ReportsSaved and waiting. It joins their Reports when they sign in.
Page shows"Check your inbox" (same for everyone)
EmailWorkflow C: "Your deal is saved. Here's your sign-in link"
⚠️ Why nobody is signed in from the page: anyone can type anyone's email into the calculator. Only the person who opens the email can get in, so a stranger can't take over someone's account.

2What happens when they click the email button

The link signs them in to their account, then checks for a password:

They...They see
Already have a passwordTheir report, right away
Don't have one yet (new, or never set one)"Set your password" screen first, then their report

If they close the "Set your password" screen, nothing in the OS opens until they set one. The next time they get in, it asks again.

GHL gets: closing-table-os:signed-up (new people), tool:max-offer-used, one stage: tag, and the cal-fund: cal-cash: cal-exp: answer tags.

3When the link is old or they come back later

  • Link expired or already used (it works once, for about an hour): the login page says "That link expired" with a "Never set a password? Set one now" button.
  • That button (and "Forgot or never set a password?") emails them a set-password link through workflow B.
  • Wrong password also shows "Never set a password? Set one now".
  • Running the calculator again always sends a fresh link.
  • Never clicks the email: the deal stays saved in their account until they do.
Backup link for any email: https://app.henrywashington.com/login?mode=forgot opens the set-password screen and never expires.

"Too many tries"Normal: max 5 tries per email per hour. Wait an hour or use a new test email.

6Test both paths (do this after any change)

Use Gmail's + trick so you never run out of "new" emails: yourname+calc1@gmail.com, yourname+calc2@gmail.com, and so on. They all land in your normal inbox, but the app treats each one as a brand-new person.

  1. New path: on henrywashington.com, run the calculator with a fresh +email, e.g. yourname+calc7@gmail.com. The page should say "Check your inbox."
  2. Open the email. Check that the From name, subject, body, button, and backup link are all there.
  3. Click Open my report. You should see "Set your password". Set one, and your report opens.
  4. Returning path: run the calculator again with the same +email, open the new email, and click the button. Your report opens right away, with no password screen. Reports should now show 2 deals.
  5. Click the same button again. It should go to the login page with "link expired". That's correct, because the link only works once.
  6. GoHighLevel → Contacts → search the +email → Tags should show tool:max-offer-used, a stage: tag, and the cal- tags, and no leftover closing-table-os:login-link.
♻️ Next time: the delta is only a new +number on the test email. The flow, workflow C, and the tags stay the same. When a new tool (Funding Path Finder) gets a website version, it follows this same two-path pattern with its own email workflow.
